### Dynamic probe differences that must not be copied verbatim

Loupe's DEVELOPMENT.md:219-232 documents read-only and changing groups. The read-only provider group includes quote/SQL-error and `../` probes that can request `/etc/hosts`; the changing group starts components and tests synthetic provider insert/update/delete cleanup. MobileAg's current implementation plan explicitly requires synthetic canaries and says not to read OS/app private data. The Loupe probe details are useful for workflow comparison only: **do not port `/etc/hosts`, app database reads, credential entry, root install, CA mutation, or unbounded generic Intent payloads.** Implement any analogous test against a researcher-owned fixture and its documented synthetic canary, with a distinct opt-in and a recorded stop/cleanup outcome.

### Confirmed source-level integration risks and limitations (not bounty findings)

These are review observations about implementing/operating Loupe, not claims of remotely exploitable vulnerabilities:

1. **Powerful local bridge is intentionally high-trust.** `proxy/server.js:25-80` dispatches ADB, Frida, certificate, decompiler and analyzer routes; the default listener is `0.0.0.0`. `proxy/auth.js:1-34` and `proxy/adb-bridge.js:99-127` add loopback, Origin, Host and per-launch bearer/WebSocket token checks, including a same-origin-only session-token mint route. This is a defense-in-depth design; binding on all interfaces alone is not proof of network reachability or an exploit. MobileAg should keep its simpler loopback-only backend and per-action policy.
2. **Two authenticated local request bodies are accumulated without an explicit size cap in the inspected handlers.** `proxy/adb-bridge.js:119-130` concatenates request data into a string for pair/connect; `proxy/cert.js:13-28` buffers the entire uploaded certificate. They sit behind Loupe's local bridge token gate, so the demonstrated concern is resource exhaustion by an authenticated local caller or compromised same-origin UI, not unauthenticated remote access. A port should enforce streaming byte caps and reject over-limit input before parsing.
3. **The device control feature is intentionally more privileged than an ordinary app.** README.md:19-29, DEVELOPMENT.md:71-155 describe arbitrary shell, root-aware operations, installs, settings, Frida and CA installation. Shell/root/device actions are operator capabilities, not evidence that an app can obtain those privileges. MobileAg must preserve this distinction in UI language and reports.
4. **Dynamic evidence can contain actual values.** DEVELOPMENT.md:208 explicitly says findings, stored results and Markdown exports may contain real secret values and calls out the local `~/.loupe/analyzer` directory as sensitive. This is an intentional evidence trade-off, but MobileAg's redaction-by-default policy should remain stronger; ported features should retain canary identifiers/metadata instead of raw credentials or provider rows.
5. **Decompiler confinement is a useful pattern, not an absolute guarantee.** `proxy/toolchain.js:1-6,65-90` pins toolchain downloads by SHA-256 and bounds download size; `proxy/sandbox.js:25-103` detects OS sandbox support and runs a canary/no-network self-test. Windows is unsupported for decompilation (DEVELOPMENT.md:190-192). Keep the self-test fail-closed and verify runtime confinement on the deployment OS before claiming equivalent isolation.
6. **Dynamic reachability is not an ordinary-app verdict.** DEVELOPMENT.md:219-232 identifies adb-shell component probes and explicitly qualifies that shell is more privileged than an ordinary app. MobileAg reports dispatch observations as `not_proven` and requires current exact scope; retain that boundary.

No demonstrated Loupe security defect is asserted in this report. Review limitations: shallow checkout, static code reading, no actual device, no production configuration review, and native-binding failure prevented all packaged tests/build from completing cleanly.

## MobileAg implementation: bounded source browser/search

**Status: implemented and locally validated.** Authenticated endpoints support bounded source reads (`GET /api/scans/{scan_id}/source?path=...`), source inventory (`.../source/files?q=...`) and literal search (`.../source/search?q=...`). Reads are capped at 1 MiB per file. Inventory/search use approved per-scan JADX/APKTool roots, descriptor-relative no-follow traversal, known text suffixes, file/entry/byte/result/time budgets, and explicit partial-coverage reasons. Search results contain paths and line numbers only, not matching source lines. The finding AST Code panel supports opening files, browsing/filtering the path inventory, and literal search; APK-derived output is rendered via `textContent` and DOM text nodes. Endpoints retain the normal MobileAg bearer-session middleware and require completed/partial scans. This is a local review convenience; it does not claim better decompiler completeness or semantic source mapping. A search limited to 500 files / 16 MiB / two seconds is not a complete repository search when coverage is partial.

Regression tests use only temporary synthetic directories and verify valid reads, traversal/absolute/backslash rejection, symlink rejection, binary rejection, size caps, bearer-auth middleware, and active-scan refusal. No existing output directory or APK was read by the implementation tests.

## Integration checklist and current disposition

The checklist below replaces a blanket "port everything" claim. It records which Loupe-inspired behavior is now present, what is still a genuine engineering gap, and what is deliberately not imported because doing so would add risky target-mutating capability or claim evidence that MobileAg cannot currently collect. No Frida/ADB device session or APK was exercised for this update.

1. **Artifact/source browser — implemented, bounded.** Inventory, literal search, finding-to-source navigation, text/Smali alternatives, and symlink-safe file reads are available. All three APIs now require the caller to bind the request to the scan's 64-character APK SHA-256; mismatches/missing scan hashes fail closed. Responses carry that hash plus the recorded decompiler status/limitations. UI labels partial/unknown decompilation and explicitly warns that absence is not evidence. Manifest/resource text is browseable when emitted by the decompiler. **Signature summary remains a gap:** MobileAg does not currently attest APK signing certificates; do not infer signer identity from the manifest or decompiler output.
2. **Dynamic build identity — not complete.** Existing scope gates bind work to package and explicit device serial, and readiness/device inventory exposes limited device metadata. It does not yet attest hashes for installed base and split APKs or compare those with the analyzed artifact. Consequently no cross-build equivalence may be claimed and a dynamic result must remain bounded to the actual recorded observation. This requires explicit-device testing and should be implemented before adding any automatic dynamic session workflow; no shell/root action is to be introduced as a shortcut.
3. **Read-only device console — current overlap, not a parity port.** MobileAg already has scoped diagnostics. Additional Loupe-style panels are not needed for source analysis and are not included. Keep exact-serial selection, current scope authorization, package/PID attribution, output caps, and separate root/shell evidence. No touch/screen input, arbitrary shell UI, package mutation, settings changes, or reboot is ported.
4. **Unified dynamic recorder — not complete.** Existing DAST/assessment records are not equivalent to Loupe's single capture lifecycle. No new recorder was added because reliable teardown and installation/build identity are prerequisites. Remaining work: bounded capture lifecycle, immutable device/build binding, explicit stop/cleanup outcome and partial/not-tested status. Do not collect app-private databases, `/etc/hosts`, credentials, or raw secret values.
5. **Workspace/UI — source workflow integrated; broad Loupe redesign not applicable.** Do not replace the Python/FastAPI UI architecture with React/Vite merely for visual parity. Keep refinements limited to usability/accessibility work validated against the existing browser regression suite.
6. **Frida/proxy — existing guarded functionality only; no broad Loupe clone.** MobileAg may use transparent, explicitly scoped observation that is already present. No hidden hooks, stealth, TLS/pinning bypass, secret/plaintext harvesting, root CA installation, or trust-store mutation is imported. This checklist does not claim those exclusions are implemented as a universal policy across every third-party integration; relevant paths still require their own review.

**Completion assessment:** The safe source-review portion is implemented and now hash-bound. The broader Loupe parity list is **not fully complete**: dynamic installed-build identity and a unified recorder remain. They cannot be honestly marked complete without implementing and testing device-bound functionality on an explicitly authorized controlled lab device. Powerful Loupe-only mutation features are intentionally excluded, not unfinished promises. Treat this report as an integration ledger, not evidence of Loupe feature parity or proof of runtime security.
