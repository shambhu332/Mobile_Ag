### Missing-state design shared across screens
- **Offline:** persistent banner; show last successful timestamp; keep read-only saved data; never fabricate graph or results; offer explicit retry for reads only.
- **Unauthorized401:** preserve safe navigation state, close privileged controls, reconnect form; no endless WS retry. **Forbidden403:** explain exact missing device/origin capability without suggesting bypass.
- **Loading:** skeleton or bounded progress with stage and cancel; disable duplicate submit; don't announce100% before durable completion.
- **Empty:** distinguish No scans / No candidates / Module skipped / Analysis failed / Not tested; contextual CTA, not a green Clean badge.
- **Partial:** module coverage checklist, failed/skipped reasons and output availability; export must retain limitations.
- **Error/timeout/rate limit:** inline summary + correlation ID, recoverable action, countdown/Retry-After if supplied; keep input values; no raw traceback or credential in toast.
- **Permission denied:** explain ordinary-app versus shell/root requirements; lack of access is inconclusive, never “no leak”.
- **Success:** only after backend acknowledgement/durable state; show job/evidence ID, scope, time and next action.

## Accessibility and design-system recommendations

Observed DOM gaps support remediation; they do not establish a full WCAG conformity level. W3C guidance covers [WCAG2.2 reflow, labels, focus and status criteria](https://www.w3.org/TR/WCAG22/). The [target-size criterion](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) has spacing/other exceptions; a sub24px count alone is not a compliance verdict.

- Use semantic navigation with `aria-current`, correct tab/panel roles where tabs are used, associated `label for` on every input, accessible names for icon actions, and an initial skip link.
- Modal/drawer: dialog name, inert background, focus containment, Escape/close, restore trigger focus. Form error summary links to inputs with `aria-invalid`/`aria-describedby`.
- Single polite live region for progress/success; persistent actionable failures rather than disappearing toast-only messages. Avoid announcing every telemetry row.
- Adopt14–16px default body/control text; ≥12px supplementary metadata with good contrast; use rem and allow selection/zoom. Global `select-none` impedes copying evidence and assistive use.
- Target44px primary hit area where practical; at least24px or qualifying spacing under WCAG2.2 minimum. Measure touch layouts and keyboard focus visibility.
- Palette tokens: background/surface/raised/border/text/muted/accent/focus/status; status includes text/icon, never just hue. Existing slate500 `#64748b` on panel `#111726` computes about3.76:1, insufficient for normal-size text when that pair is used; slate400 is a better starting point. Check actual composited/hover/disabled states before claiming whole-screen contrast failure.
- Respect `prefers-reduced-motion`; remove unnecessary pulse/ping for persistent online status; reserve animation for short progress transitions. Graph must have a keyboard-accessible table/list alternative.
- Spacing scale4/8/12/16/24/32; radii8/12; consistent border and modest shadows. Reusable Button(primary/secondary/danger), Input, Select, FormField, Alert, EmptyState, Progress, StatusBadge, EvidenceCard, ConfirmDialog, Table and Drawer replace per-screen ad-hoc styling.
- Use one product/version source; remove Enterprise/Autonomous/Verified claims where unsupported. Display runtime package version0.1.0 rather than conflicting hardcoded2.2 values.

## Redesigned UI-driven workflow
1. **Connect & readiness:** token connection; show local/remote transport, offline policy, tools and unsupported capabilities. No fake ready indicators.
2. **Create project/scope:** named authorization record, exact allowed device/package/origin, researcher-owned test account designation. Persist/enforce on server; UI merely edits policy.
3. **Upload APK/IPA:** show artifact SHA256,size,platform; no arbitrary server pathname field. Validate then retain immutable original.
4. **Review scan:** Static-only default; explicit Cloud data-sharing consent; optional device actions require scoped selection and plan. Show actual supported options and effective config.
5. **Run:** queued/running/stage/coverage/cancel; offline failures remain partial not clean. Jobs survive browser disconnect; server restart recovery is explicit.
6. **Review findings:** candidates first; source/decompilation caveat, attacker prerequisites, confidence versus impact separately; inspect evidence without executing it.
7. **Validate:** request-specific safe action preview; explicit device/build/privilege mode; attach observed evidence and controls. Generated PoC text never becomes captured evidence automatically.
8. **Triage/export:** durable per-scan verdict, revision/author/time/evidence requirements; redacted JSON/Markdown/SARIF agree; export scope and limitations.
9. **Retain/clean up:** storage/retention controls, reversible archive where practical, separate destructive deletion confirmation and clear backup policy.

A UI-driven workflow does **not** mean all controls are UI-only: authorization, egress, storage, job execution and evidence persistence need unavoidable backend/code changes. The goal is for the operator to use the finished UI safely without manually editing backend files for each scan.
